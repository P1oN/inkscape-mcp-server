## Source archive regression

Preparing a committed source archive exposed Git's `pax_global_header` as a retained tar
member. The strict native extractor correctly rejected this special member before writing
source files. The source exporter now omits only Git's global PAX metadata; source identity
remains in the explicit `SOURCE_REVISION`, and extraction protections are unchanged.

The committed/working-tree source regression now asserts that every exported member is
an accepted file, directory or contained link, while retaining original file contents,
source revision/working-tree distinctions and refusal to overwrite an existing archive.
The new assertion failed before the repair with `XGlobalHeader`, and the complete tooling
graph passed afterward (15 tests); tooling fmt/Clippy passed. Local retained evidence is
under `migration/results/release-v0.1.2-candidate/` and the `/tmp/v012-*` diagnostic logs.
A fresh committed archive must pass Git-free isolated source installation before publication.

uploaded. Published release notes and asset metadata record the final source revision,
SHA-256 values, package acceptance, and CI run links. Source installation acceptance uses
an isolated client profile on the existing development host, not a clean-machine claim.
